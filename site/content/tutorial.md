以下是第一次装机的完整步骤。用 Windows 电脑烧录系统卡，再打开 DuckBuddy 工作台做测试和标定。HD-1910 版先看[这几处装机差异](#hd-1910)。

## 准备什么 {#prepare}

| 类别 | 东西 | 说明 |
|---|---|---|
| 机器人 | 组装好的机器鸭 | Orange Pi Zero 3W + HAT + PDB，15 只 HL-2915 或 HD-1910 舵机，舵机 ID 已设好（1–15）。零件见 [物料清单](bom.html) |
| 机器人 | 锂电池 | HL-2915 用 3S LiPo（满充 12.60 V）或 3S LiHV（满充 13.05 V）。HD-1910 用普通 2S LiPo（满充 8.40 V）。详见[充电](#charge) |
| 存储 | TF 卡 16 GB 以上 + 读卡器 | 镜像约 9.5 GB |
| 电脑 | Windows 10/11 | 和机器鸭连在同一个 WiFi 里 |
| 电脑 | 系统镜像 | 下载 [r14 预览镜像](https://github.com/Animan-AI/DuckBuddy/releases/tag/opi-image-r14)的 `.7z` 和 `.img.sha256`。[原有 r8](https://github.com/Animan-AI/DuckBuddy/releases/tag/opi-image-r8) 和[百度网盘 r4](https://pan.baidu.com/s/14wBtz3ptDRZAbFjLD1jfiQ?pwd=njvh)（提取码 `njvh`）也可下载 |
| 电脑 | balenaEtcher | 烧卡软件，[etcher.balena.io](https://etcher.balena.io) |
| 电脑 | Python 3.11 以上 | 装好后运行 `pip install pyserial mujoco numpy Pillow` |
| 电脑 | DuckBuddy 仓库 | 从 [github.com/Animan-AI/DuckBuddy](https://github.com/Animan-AI/DuckBuddy) 下载：用 `git clone`，或点 Code → Download ZIP 后解压。工作台在 `tools/bringup`，零位标定还要用到 `tools/joint_align` |
| 网络 | 2.4 GHz WiFi | 路由器或手机热点都行 |
| 备用 | mini HDMI 线 + 显示器 + USB 键盘 | 只在连不上 WiFi 时用 |
| 备用 | 蓝牙手柄 | 支持经典蓝牙 Xbox 模式的手柄，例如 [BSP-G6](#gamepad-bsp-g6) |

机器鸭要用的软件，镜像里已经全部装好，不用另外安装。

## 第一步：烧录系统卡 {#step1}

烧一张卡约 10–15 分钟。

### r14 镜像说明 {#image-r14}

从 [GitHub 发布页](https://github.com/Animan-AI/DuckBuddy/releases/tag/opi-image-r14)下载 `.7z` 和 `.img.sha256`，把两个文件放在同一个文件夹。用 7-Zip 解压 `.7z`，得到 `DuckBuddy-opizero3w-trixie-20261126-r14-hd1910.img`。

- **HD-1910（2S）**是 r14 初始机型，用普通 2S LiPo，满充 8.4 V。完成标定后可加载 DuckBuddy 自训的行走 8498、起身／站立 9997 和坐站 6998。
- **HL-2915（3S）**也可以刷 r14。开机连网后，先在工作台切换到 [HL-2915（3S）](#select-model)，再做关节映射和零位标定。
- **手机热点配网**可在下拉列表选择附近的 Wi‑Fi。联网后打开 `http://鸭子的IP:8088/`，可以看动作模型、预览摄像头、拍照并下载。完成标定并启用整机服务后，网页驾驶舱可以操作已加载的动作。

HD-1910 的 8498 和分关节 PD 有小黑的实机记录，r14 的驾驶舱和相机后台已实机测试通过。r14 整卡首启和行走仍按预览版记录。[查看配套模型、实测 PD 和复现步骤](https://github.com/Animan-AI/DuckBuddy/tree/main/deploy/opi-image/r14)。

1. **核对镜像没有下坏。** 在镜像所在的文件夹里打开 PowerShell，运行：

    ```powershell
    Get-FileHash .\DuckBuddy-opizero3w-trixie-*.img -Algorithm SHA256
    ```

    把输出的一长串和 `.sha256` 文件里的对一下，完全一样才继续。

2. **插卡、打开 balenaEtcher。** 依次点 Flash from file（选镜像）→ Select target（选 TF 卡，看清容量，别选成移动硬盘）→ Flash。
3. **等它写完并校验完。** 界面显示 Flash Complete 才算成功。
4. **Windows 弹出“需要格式化磁盘”时，点取消。** 卡里是 Linux 分区，Windows 读不了，点了格式化就白烧了。
5. 弹出读卡器，取下卡。

一张卡对应一只鸭子。用过的卡里存着那只鸭子的标定和名字，不要直接插到另一只上用。

## 第二步：第一次开机与连网 {#step2}

第一次开机要 2–3 分钟，中间可能自己重启一次，别断电。这次开机它会做三件事：

- 把分区扩到整张卡；
- 按芯片序列号给自己起名 `duck-XXXX`（XXXX 是 4 位字母数字）；
- 生成这只鸭子自己的叫声。

1. 把卡插进 Orange Pi。断电时先按[摄像头排线和 ToF 焊接实拍](assembly.html#camera-tof)检查头部接线。用 **PH2.0 3P 双头反向线（300 mm）**连接 PDB J5 和 HAT J2，对照[两块板的接线图](assembly.html#pdb-hat-wiring)逐根核对 GND、VBAT 和 DATA，再把电池接上 PDB。这时舵机还不上力，可以让鸭子平躺在桌上。
2. **让它连上 WiFi。** 按你的镜像版本选择：
    - **r14 手机热点配网。** r10、r11 等热点预览版也可用。没装摄像头也能用，按下面的[手机热点配网](#hotspot-r10)操作。
    - **r4 或更新版的语音扫码。** 开机前接好麦克风、扬声器和摄像头。等系统启动后说「豆豆，扫码」，听到提示后把手机上的 Wi‑Fi 分享二维码放在摄像头前约 20–30 厘米，保持一两秒。连上后会逐位播报 IPv4 地址，也可以说「豆豆，IP 是多少」再听一次。记下 IP 后跳到第 4 条，用 IP 登录。用 r14 扫不到码时，也可以说「豆豆，热点」重听配网指引。
    - 镜像文件名带 `-wifi`（课程会场用的）：开机会自动连上会场 WiFi，直接看第 3 条。
    - 旧版或语音配网失败：接 mini HDMI 显示器和 USB 键盘，屏幕上会出现 `duck-XXXX login:`（顺便记下这个名字）。用户名和密码都是 `orangepi`。登录后运行 `sudo nmtui`，选 Activate a connection，挑你的 WiFi，输入密码。连上后运行 `ip -4 a show wlan0`，`inet` 后面就是 IP。
    - 没有显示器：用 USB 串口调试板接板子的调试口，在电脑上用串口工具（波特率 115200）登录，后面的操作同上。
3. **在电脑上找到它。** 打开 PowerShell：

    ```powershell
    ping duck-XXXX.local
    ```

    能通就用这个名字。如果不知道 XXXX，或者 `.local` 不通，就去路由器管理页的设备列表里，找名字以 `duck-` 开头的设备，用它的 IP。

4. **第一次登录并改密码。** 记下鸭子的 IP，按[第三步](#step3)先手动 SSH 登录，再给这台电脑配置免密登录。

连上工作台后，在标定前[确认整机机型](#select-model)。

后面凡是写 `duck-XXXX.local` 的地方，都换成你这只鸭子的名字，或者直接写 IP。

### 用手机连接鸭子的配网热点 {#hotspot-r10}

1. 刷好 [r14 预览镜像](https://github.com/Animan-AI/DuckBuddy/releases/tag/opi-image-r14)，插卡开机，等首次启动完成。有麦克风和扬声器时，也可以说「豆豆，热点」听操作指引。
2. 在手机的 Wi‑Fi 设置中连接 **`DuckBuddy-XXXXXX`**，密码是 **`duck2026`**（字母小写）。如果手机提示这个热点无法上网，选「保持连接」。
3. 打开手机浏览器，在地址栏输入 **`http://10.42.0.1/`**。在下拉列表选择要加入的 Wi‑Fi，再输入密码。隐藏网络可选「手动输入网络名称」。旧版页面可直接填名称。家用网络通常选 WPA / WPA2，纯 WPA3 的网络选 WPA3 专用。点「连接 Wi‑Fi」。
4. 提交后，鸭子的热点会暂时消失。连接成功后，鸭子会留在家里的 Wi‑Fi。有扬声器时会播报 IP。也可以把手机连回同一个 Wi‑Fi，在路由器的设备列表找以 `duck-` 开头的主机。
5. 如果连不上，约一分钟内 `DuckBuddy-XXXXXX` 热点会恢复。手机重新连进去，核对名称、密码和加密方式后再试。

拿到 IP 后，按上面的「第一次登录并改密码」登录，再做[工作台免密登录](#step3)。

## 第三步：首次或重刷后配置 SSH 免密登录 {#step3}

让电脑和鸭子接入同一个局域网。在 Windows PowerShell 里完成下面几步。重刷后，电脑原来的 SSH 密钥可以继续用，需要在新系统里重新安装公钥。工作台「总览 → SSH 免密登录 / 重新刷机」也会按当前地址显示命令。

1. **填入鸭子现在的地址。** 用开机播报的实际 IP 替换示例里的 `192.168.1.50`，下面几条命令都在同一个 PowerShell 窗口执行。

    ```powershell
    $DuckHost = '192.168.1.50'
    $Duck = "orangepi@$DuckHost"
    ```

2. **重刷时清除旧主机记录。** 电脑会记住上一次连接的主机密钥。重新刷卡后，即使 IP 一样，也可能提示 `REMOTE HOST IDENTIFICATION HAS CHANGED`。确认地址属于刚重刷的鸭子，再执行下面的命令。提示没有旧记录可以继续。首次连接可直接做下一步。

    ```powershell
    ssh-keygen -R $DuckHost
    ```

3. **手动登录，确认新主机。** 看到 `Are you sure you want to continue connecting` 时，核对地址再输入 `yes`。DuckBuddy 镜像的初始密码是 `orangepi`，改过就用新密码。输入密码时屏幕不会显示字符。登录后可用 `passwd` 修改初始密码，再输入 `exit` 回到电脑。

    ```powershell
    ssh $Duck
    ```

4. **重新安装电脑的公钥。** 如果已经有 `id_ed25519.pub`，可以直接用。没有这个文件时，在电脑运行 `ssh-keygen -t ed25519`，使用默认保存位置。再执行下面的命令，按提示输入鸭子当前的登录密码。

    ```powershell
    Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub" | ssh $Duck 'umask 077; mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys && sync'
    ```

5. **先确认免密登录，再确认工作台。** 在电脑执行：

    ```powershell
    ssh -o BatchMode=yes $Duck hostname
    ```

    能直接显示主机名（例如 `duck-0000`），且没有索要密码，就说明免密登录成功。回到工作台「总览」点 **重连代理**，页头显示鸭子的主机名和地址即为连上。刷机后 IP 变了，按[第四步](#step4)用新地址重新启动工作台。

    手动登录成功，但免密命令报 `Permission denied`，回第 4 步检查公钥有没有装到这台鸭子的 `orangepi` 账户。提示 `Host key verification failed` 时回第 2、3 步核对主机记录。手动登录也超时，就先确认 IP 和局域网连接。

## 第四步：打开 DuckBuddy 工作台 {#step4}

工作台是在你电脑上运行的网页工具，通过 ssh 指挥鸭子做测试和标定，鸭子上不用装任何东西。

1. 从 [DuckBuddy 仓库](https://github.com/Animan-AI/DuckBuddy) 下载最新版。原来用 Git 克隆的可以在仓库目录执行 `git pull --ff-only`。在同一个 PowerShell 窗口运行：

    ```powershell
    python tools/bringup/app.py --host $Duck
    ```

    如果换了 PowerShell 窗口，把 `$Duck` 换成完整地址，例如 `orangepi@192.168.1.50`。

2. 在浏览器里打开 `http://localhost:8780`。
3. 点「总览」里的 **刷新**，页头显示出 `duck-XXXX` 就是连上了。新卡上 robotd 显示「未运行」是正常的，完成标定后再启用运动服务。

### 标定前确认整机机型 {#select-model}

在工作台打开 **「总览 → 整机机型」**，按实物舵机和电池选择，并点「应用到机器人」。

| 你的机器鸭 | 刷 r14 后 | 使用较旧的镜像 |
|---|---|---|
| HD-1910（普通 2S LiPo） | 默认已选 HD-1910（2S），看到机型正确即可继续 | 如果仍显示 HL-2915，选 HD-1910（2S）并应用 |
| HL-2915（3S） | 先选 HL-2915（3S）并应用，再标定 | 看到 HL-2915（3S）即可继续 |

已在鸭子 SSH 终端时，也可运行 `duck-model` 查看当前机型。需要切换时，执行 `duck-model hl2915` 或 `duck-model hd1910`。

工作台有五个页签，每个页签顶上都有一段可以展开的图文说明：

| 页签 | 做什么 | 本教程哪一步用 |
|---|---|---|
| 总览 | 首次连接 SSH 指引、连接状态、启动 / 停止 robotd、选 USB 调试板串口 | 每一步 |
| 整机测试 | 舵机总线、IMU、麦克风、喇叭、ToF、摄像头六项检测 | 第五步 |
| 舵机 | 扫描、改 ID、摆动、关节映射 | 第六步 |
| 零位标定 | 核对关节方向、记录零位、站在 home 姿势上精调 | 第七步 |
| IMU 固件 | 用 ST-Link 给 PDB 上的 IMU 烧固件 | 板子没烧过固件时才用 |

**页头右边红色的「全部卸力」随时都能按。** 舵机乱动、发烫或有焦味时，先按它，再拔电池。

## 第五步：板级测试 {#step5}

六项全部通过才能往下做。打开「整机测试」，确认 robotd 没在运行（新卡本来就没运行），然后逐项点测试。每项都会给出通过 / 不通过和测量值。

| 项目 | 你要做的 | 通过的标准 |
|---|---|---|
| 舵机总线 | 点测试就行 | 15 只全部应答，错误率 ≤ 0.5%，没有红色的多圈读数 |
| IMU | 让鸭子静止放着 | 融合输出 90–150 Hz，陀螺噪声 < 1 dps |
| 麦克风 | 在录音的 4 秒里拍拍手或说说话 | 两路都有声音，没有削顶 |
| 喇叭 | 听到 1 kHz 的“嘟”声后点“听到了” | 录到的声音高出 ≥ 15 dB，并且人耳听得到 |
| ToF | 点测试就行 | ≥ 10 Hz，64 个点里至少 32 个有效 |
| 摄像头 | 镜头前别挡着 | ≥ 10 fps，缩略图是正常画面 |

不通过时，先对照下面几种常见情况：

- **舵机总线、IMU、麦克风、ToF 一起不通过**，连 IMU（ID 200）都不应答：HAT 的 3.3 V 没有电。断电后检查 HAT 上的 U5（正面，印 TJ）和 U7（背面，印 SH）是不是装反了。
- **每个 ID 都回 `ff ff 00`**：断电后，按[接线图](assembly.html#pdb-hat-wiring)确认 PH2.0 3P 反向线的 GND、VBAT 和 DATA 是否逐根对通。
- **只有 IMU 不应答**：PDB 上的 IMU 还没烧固件，用「IMU 固件」页烧。
- **ToF 0 帧**：多半是插头没插实，断电重插。
- **只有少数舵机不应答**：检查这几只的串线和插头。
- **HD-1910 版：某只舵机读数小于 0 或大于 4095**：这是多圈计数，关节被掰过了 0/4095 那一点。重启 Orange Pi 清不掉，要拔电池给舵机断电。上力之前，15 只的读数都要在 0–4095 之间，否则它会多转一圈去找目标。

全部通过后点“导出报告”，存一份 JSON，以后维修时可以对照。

## 第六步：关节映射 {#step6}

这一步告诉鸭子：哪个 ID 的舵机装在哪个关节上。装配时很少按顺序装，所以每只鸭子都要做一次，约 10 分钟。

1. 让鸭子平躺在桌上，腿和头都悬空，能自由摆动。
2. 确认「总览」里 robotd 是停着的。robotd 运行时，舵机页会拒绝操作。
3. 打开「舵机」页的 **关节映射** 卡片，点开始。工具会让舵机一只一只地左右摆动 ±8°，你看哪个关节在动，就在页面上点那个关节。嘴也算一个关节。
4. 15 只都点完后，做一遍 **左右对照**：左右成对的关节一起摆，确认没有点反左右。
5. 选 **不改 ID，写入配置**。工具会先备份，再把对应关系写进鸭子上 `~/robot/duck.toml` 的 `joint_ids`。

另一个选项“按关节顺序批量改 ID”也能用，但会改写 15 只舵机的内存，第一次做不建议用。

## 第七步：零位标定 {#step7}

这一步确定每个关节的方向和“零度”位置，决定鸭子能不能站稳。它是整个流程里最需要耐心的一步，约 30–60 分钟。

**先做准备：**

1. 关掉旧标定页，在启动工作台的 PowerShell 按 **Ctrl+C**，再用同一条命令重开。这样标定页会读取刚保存的关节映射。若提示「机器人配置有更新」，也用这个办法重新读配置。
2. 托稳鸭子或把躯干放稳，打开「零位标定」，点 **开始标定**。工作台会启动 robotd，标定页第一次连上时会让全身卸力。等看到实机关节读数再继续。

**核对方向（舵机不上力，用手掰）：**

1. 在表格里点一个关节，第三张图会画出它的正方向。
2. 把实机的这个关节往同一个方向掰。前两张图里的模型应该跟着同向转，读数变大。
3. 转反了，就点这一行的 **反向**，再掰一次确认。
4. 15 个关节都做一遍。左右成对的关节要两边一起掰，只掰一边容易看反。嘴没有模型：张嘴时读数应该变大。

**先记一版粗零位：**

1. “参考”选 **零位**，照着参考图把鸭子摆好：腿伸直、头摆正、嘴闭到底。
2. 点 **记录全身粗零位**。这会生成一份零位草稿，整机摆到大致正确即可。
3. 如果只有一两轴偏，把它们分别摆正，点 **记录所选关节的零位**。全身粗零位会覆盖已经做过的逐轴调整，所以做完粗调后，剩下的差异只修对应的轴。

### 回零位、回站姿 home 和保存有什么区别？ {#calibration-buttons}

**零位**是每个关节的 0° 参考，**站姿 home** 是一整套站立角度，髋和膝会按模型弯曲。人在摆站姿时，如果要用它做标定，切到「参考 → 站姿 home」，再记录对应的站姿角度。

| 按钮 | 会做什么 |
|---|---|
| **回零位** | 按本页的零位草稿上力到关节 0°，保持姿势，同时打开滑杆。用来检查机械零位。 |
| **回站姿 home** | 按已保存到机器人的标定上力，摆出站姿。页面里的零位草稿还可以继续改。 |
| **保存零位** | 将当前草稿写到机器人，生成备份后重启 robotd。用来保留刚调好的零位。 |
| **保存并回 home** | 保存当前草稿，加载新标定后上力回站姿。操作前先卸力、托稳鸭子。 |

### 用滑杆微调并保存 {#calibration-sliders}

1. **先托稳，把关节摆近零位，再点「回零位」。** 工作台会自动交接总线。如果是在站姿调某一轴，先回站姿，再托稳并点「保持当前位置」开始微调。
2. **只调偏的那一轴。** 滑杆每格 0.5°，松开后发送新目标。此时表格和模型显示的是接管前的读数，以实机位置为准。
3. **点「卸力并应用微调」。** 滑杆的改动进入本页零位草稿。单点「卸力」会结束微调，滑杆改动不会计入草稿。
4. **先复查，再保存。** 从零位开始微调，可以再「回零位」复查，复查后先卸力，再点 **保存零位**。从站姿开始微调，可以直接点 **保存并回 home** 检查效果。页面显示「有未保存的零位草稿」时，改动还在本页。看到保存成功和备份路径后再关页面。
5. **复核站姿。** 托稳后点「回站姿 home」，把双脚放到平整表面，检查脚底能贴平、脚尖朝向和左右脚前后位置、躯干是否接近水平。还有小偏差，就只调整对应的轴。

保存时，工作台会把已验证型号 **HL-2915** 的机械零位同步到舵机中位 2048。**HD-1910** 通过配置里的偏移记录零位，所以保存后的原始读数可以离 2048 有一段距离。

### 偏移太大时怎么退出循环 {#calibration-wrap}

先托稳、卸力，记下报错的 **关节名或 ID**。按下面的情况处理，再只复测这一轴。

| 提示或现象 | 处理 |
|---|---|
| **离目标超过 30°**，或滑杆越调越偏 | 回零位前先用手按零位图把这一轴摆近。核对映射和方向，重新记录所选关节零位，再回零位复查。大角度偏差用手重新摆位和记录，滑杆用于小幅修正。 |
| **零位超出舵机单圈范围**，或**保存会跨过跳变点** | 先确认「参考」选对了，特别是有没有把站姿记成 0°。将这轴卸力摆到机械零位，再查看原始读数。读数仍贴近 0 或 4095 时，按下一行检查舵机的跳变点。 |
| 读数 **小于 0 或大于 4095**，或机械零位总靠近 **0 / 4095** | 多圈读数先给舵机断电再上电。若实际零位依旧贴着跳变点，断电检查或重装这轴舵盘，让机械零位落到单圈中段，再重标这一轴。已确认的 HL-2915 也可在单圈读数正常、卸力且确认实际零位时，先停 robotd，再用「舵机 → 当前位置设为中位」移动跳变点。做完重开工作台，先确认这轴在需要的行程内读数连续，再记录零位。 |
| 回站姿看起来还和上次一样 | 「回站姿 home」用的是已保存的标定。检查有没有依次点「卸力并应用微调」和「保存零位」，以及保存有没有报错。误调的草稿可用「撤销改动」回到上次已保存值。 |

如果保存后才发现大偏差，先保留页面显示的备份路径。HL-2915 保存时可能写入舵机中位，恢复旧标定时要一起核对对应的舵机中位备份和 TOML 配置。

调好后，托稳并卸力，再停止 robotd。在「整机测试」里跑一遍「舵机总线」，导出报告存档。

## 第八步：启用整机服务与首次行走 {#step8}

完成关节映射和零位标定并保存配置后，启用舵机控制、手柄、生命层、语音、视觉、ToF 和手机网页。这些服务之后会随系统启动。

1. **先托稳鸭子，打开最新版工作台。** 在「总览 → 行走与手柄」点「启用整机服务」，确认后工作台会加入当前机型的步态策略，必要时重启 robotd，并启动手柄等服务。
2. **检查启动结果。** 「行走与手柄」应显示手柄服务运行中，并列出已配置的行走策略。如果工作台没有这个入口，但鸭子上有 `duck-services`，可以在 SSH 里运行 `duck-services on`，再用 `duck-services status` 检查各项服务。
3. **用手柄开始行走。** 初次配对见[第九步](#step9)。已配对的手柄按 Home 回连。先托稳鸭子，按一下 **Start** 启用行走。确认站稳后，把它放到平整、不滑的地面，再轻推左摇杆测试前进。标定页的「回 home」只用于检查站姿，之后还要启用行走才能用摇杆前进。
4. **也可以用语音试站立。** 双手托住鸭子，对它说「豆豆，站起来」（改过名字就用新名字）。可用的动作可以在 r14 机身后台的「动作模型」查看。

**网页驾驶舱（r14）。** 在同一局域网用浏览器打开 `http://鸭子的IP:8088/`。先启用行走，再长按方向按钮。电脑也可以用 `WASD` 移动、`Q/E` 转向。松手即停止移动。r14 的 HD-1910 配置加载了坐站模型，旧镜像请以实际加载的模型为准。

安全规矩，每一条都要做到：

- 只在平整、不滑的地面上站和走，周围留出 1 米，不要在桌边。
- 第一次站、第一次走时，人要蹲在旁边，手随时能接住它。
- 出了问题，先点工作台的「全部卸力」（HL-2915 版也可以说“豆豆，睡觉”），再拔电池。
- 头部舵机到 70 °C 时，它会自己停下来休息。这是正常的保护，等它凉下来就好。
- 要回去重新标定：先让它躺下，运行 `duck-services off`，再用工作台。

### r2 镜像安装配对服务 {#gamepad-r2}

**已刷 `-r2` 的用户可以保留现有系统。** `-r2` 已有蓝牙驱动和兼容设置，需要先在鸭子上安装一次配对服务，再用最新版工作台操作。

1. 让电脑和鸭子连到同一局域网，按[第三步](#step3)配置 SSH 登录。用 `ssh orangepi@鸭子的IP` 登录，在鸭子的终端执行以下命令。已有仓库时，在现有仓库更新到最新版后，从 `sudo apt install` 开始执行。

   ```bash
   git clone https://github.com/Animan-AI/DuckBuddy.git
   cd DuckBuddy
   sudo apt install bluez python3-dbus python3-gi
   sudo install -m 755 deploy/opi-image/duck-gamepad-pair.py /usr/local/sbin/duck-gamepad-pair
   sudo install -m 644 deploy/opi-image/duck-gamepad-pair.service /etc/systemd/system/
   sudo systemctl enable --now duck-gamepad-pair.service
   ```

2. 在电脑上更新 DuckBuddy 仓库，按[第四步](#step4)重新打开工作台，再按[BSP-G6 配对步骤](#gamepad-bsp-g6)操作。服务刚启动时可能已经在扫描，此时按钮会显示本轮配对结果。

### 用终端手动配对

**配对手柄（只需做一次）。** 把手柄切到 Xbox 模式并进入配对状态（灯快闪），然后在鸭子上运行 `bluetoothctl`，依次输入：

```bash
power on
agent on
default-agent
menu scan
transport bredr
back
scan on
```

等列表里出现手柄的名字，记下它前面的地址（形如 `83:26:09:02:6A:A0`），再输入：

```bash
scan off
pair 手柄地址
trust 手柄地址
exit
```

之后按手柄的 Home 键，它会自动连上鸭子。以后每次开机，也是按 Home 键回连。

**给它起名字。** 名字和性格写在鸭子上的 `~/.config/duck/persona.json` 里，只需要写和例子不一样的部分（完整的例子在 `~/persona/example.json`）。用 `nano ~/.config/duck/persona.json` 新建这个文件，比如：

```json
{
  "name": "小鸭",
  "name_pinyin": "xiao3 ya1",
  "name_aliases": ["小丫", "小雅", "晓鸭"],
  "description": "小鸭是一只二十厘米高的小机器鸭子。它会走路、坐下、转头、嘎嘎叫，听得懂中文，用鸭叫和动作回应。",
  "character": "你是小鸭，一只小机器鸭子，性格温和、好奇，喜欢和人待在一起。"
}
```

- `name_aliases`：语音识别把名字听错时会写成的词。先空着，叫它几次名字，再用 `tail -n 30 ~/robot/recs/voiced-service.log` 看它听成了什么，把听错的词加进来。不要加单个字。
- 保存后重启三个服务才会生效：`systemctl --user restart lifed-dev voiced-dev duckweb-dev`。

**手机网页。** 手机和鸭子连同一个 WiFi，在浏览器里打开 `http://鸭子的IP:8088`，能看到它听到了什么、说了什么，以及它现在的状态。安卓手机大多不认 `.local` 名字，要用 IP。

**用语音连新 WiFi。** 对它说“（名字）连网”，把手机上 WiFi 或个人热点的分享二维码举到它脸前 20–30 厘米，它连上后会念出自己的网页地址。之后问“（名字）你的地址”，它会再念一遍。带鸭子去新地方时就用这个办法。

## 配置大模型与声音（r8） {#online-model}

让电脑和豆豆连在同一局域网，打开 `http://鸭子的IP:8088/`，展开「大模型与声音」。

1. 在「大模型 API」选择服务，填写该平台的 API Key 并保存。r8 默认选择智谱 GLM‑4.6V‑Flash，也可以选阿里千问、火山方舟、DeepSeek、OpenRouter 或兼容接口。
2. 标定后按第八步启用整机服务，再问豆豆一句话，确认能收到大模型的回复。Wi‑Fi 连通和模型认证是两件事。收到 401 时，请核对所选平台和 Key。收到 429 时，请查看供应商的速率或用量限制。
3. 在「TTS API」可选微软 Edge TTS、智谱 GLM-TTS、硅基流动或兼容接口。默认使用 Edge 晓晓。网页可以切换人声和鸭语，也可以说「豆豆，切换到人声」或「豆豆，切换到鸭语」。人声聊天支持边生成边播报。

切回已配置的供应商和接口时会自动恢复该处保存的 Key。Key 只保存于本机，公开镜像没有预填。已经标定好的鸭子要换卡时，先备份原卡的机器人配置。

## HD-1910 版要注意 {#hd-1910}

这些是装第一只 HD-1910 鸭子时踩过的坑，HL-2915 版不用管。

- **只能用 2S 电池。** 舵机由电池直接供电，插上 3S 会直接烧坏舵机，软件拦不住。2S 和 3S 电池要用不同的插头，免得插错。
- **扩展板要先换一颗电阻。** 把 HAT 上的 R11 从 130 kΩ 换成 91 kΩ（只换 R11，R6 别动），不然 2S 下 HAT 起不来。
- **PDB 的舵机座要反向焊。** HD-1910 原装线的针序和 PDB 相反，所以 J4/J6 座子要反过来焊（线的 1 号针对丝印 3/D）。第一片焊完，先测一下通断。焊完后用异丙醇刷洗干净：助焊膏残留会导电，让总线成片出错。
- **新舵机先过向导。** HD-1910 出厂是模式 4，直接用会失控。在工作台「舵机」页用新舵机向导，选 HD-1910，它会写好 ID、500k 波特率、模式 0 和卸载条件。只改了 ID 的舵机不能用。
- **多圈计数。** 关节被掰过 0/4095 后，读数会变成负数或大于 4095，要拔电池断电才能清掉。上力前先看一眼（见第五步）。
- **电量低于约 30% 时，别让它起身。** 2S 电压掉得快，起一次身就可能把扩展板的电压拉到关断线以下，导致整机重启。尽量用内阻小的电池。
- **先核对机型。** r14 默认 HD-1910（2S），旧镜像可能需要在工作台[切换整机机型](#select-model)。
- **重量。** 策略按 806 g 的整机训练。外壳或电池明显更重时，站立和走路的余量会变小。

## 常见问题 {#faq}

| 现象 | 多半是 | 怎么办 |
|---|---|---|
| 插卡后 Windows 要求格式化 | 卡里是 Linux 分区 | 点取消，不影响使用 |
| `ping duck-XXXX.local` 不通 | 网络不支持这种名字，或鸭子没连上 WiFi | 去路由器设备列表找 IP；找不到就接显示器，用 `nmtui` 重连 |
| 工作台报连不上机器人 | SSH 主机密钥、免密登录或地址有问题 | 展开「总览 → SSH 免密登录 / 重新刷机」，按[第三步](#step3)核对旧主机记录、重装公钥并验证免密连接 |
| 舵机页拒绝操作 | robotd 占着总线 | 在「总览」里停掉 robotd；服务已经打开的用 `duck-services off` |
| 开始标定后一直没有实机读数 | robotd 没有读到总线 | 到「总览」看 robotd 状态，核对舵机应答和关节映射 |
| 滑杆调过，重开却变回原样 | 微调还在草稿里，或换了配置 | 按「卸力并应用微调」→「保存零位」，等成功提示再关闭。写完映射或手动改配置后重开工作台 |
| 零位偏移过大或读数显示多圈 | 参考选错、机械零位靠跳变点，或转过单圈边界 | 按[偏移过大的处理步骤](#calibration-wrap)卸力并检查报错的单轴 |
| 叫名字没反应 | 语音识别把名字听成了别的字 | 看 voiced 日志，把听错的词加进 `name_aliases` |
| 走着走着不听摇杆了 | 头部舵机到了 70 °C，在休息 | 等它凉到 45 °C 以下自己恢复 |
| 电池一接上就报电压不对 | 电池节数和舵机不配（HL-2915 要 3S、HD-1910 要 2S），2S 充到了 8.4 V 以上，或者电量太低 | 换节数对、充满的电池，再在工作台[确认整机机型](#select-model)与实物一致 |
| 手柄连不上 | 手柄还没进 Xbox 配对模式，或在回连另一台设备 | BSP-G6 拨到 X 档，长按 Home 到灯快闪，再用工作台配对。用终端配对时选 `transport bredr` |
| 手柄灯常亮，摇杆推了不走 | 行走控制尚未启用，或手柄服务没启动 | 在工作台「总览」确认手柄服务运行，托稳鸭子再短按 Start（≡） |
| 摄像头测试报“被占用” | visiond 在用摄像头 | `systemctl --user stop visiond-dev` 后再测 |

| 命令 | 作用 |
|---|---|
| `duck-services status` | 看七个服务是否在运行、策略加了没有 |
| `duck-services on` | 标定完后打开全部服务，开机自启 |
| `duck-services off` | 停掉全部服务，回到标定状态（先让它躺下） |
| `duck-model` | 看 / 切换舵机型号（`hl2915` 或 `hd1910`） |
| `systemctl --user restart lifed-dev voiced-dev duckweb-dev` | 改完名字后让它生效 |
| `tail -n 30 ~/robot/recs/robotd-service.log` | 看舵机控制的日志；把 robotd 换成 lifed / voiced / padd，看对应服务的日志 |
| `cat /var/lib/duck/firstboot.log` | 看第一次开机时起名和生成叫声有没有成功 |
| `ip -4 a show wlan0` | 看 IP |
| `sudo nmtui` | 连别的 WiFi |
| `passwd` | 改登录密码 |
| `sudo poweroff` | 关机。等系统关机后再拔电池，见[关机步骤](#charge) |

工作台的更多用法（新舵机配置向导、IMU 烧录、各项测试的判据）见仓库里的 [`tools/bringup/README.md`](https://github.com/Animan-AI/DuckBuddy/blob/main/tools/bringup/README.md)。
